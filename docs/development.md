# Разработка

## Локальные проверки

Используйте Python 3.12 и [makeapp](https://pypi.org/project/makeapp/).
Из каталога пакета:

```bash
ma tools
ma tests
```

Единственная версия проверок — Python 3.12. Makeapp читает матрицу из
[`python-package.yml`](../.github/workflows/python-package.yml); отдельной локальной матрицы нет.
GitHub Actions запускает этот workflow при push и pull request на Ubuntu:
uv устанавливает группу `tests`, затем запускается pytest напрямую, без makeapp.
Линтеров, сборки приложений для стика и публикации в workflow нет.
Установка CLI описана в [README](../README.md#установка).
После изменения точки входа или ресурсов проверьте установленную команду
из постороннего каталога через `iroll --help` и `iroll list --json`.

Тесты используют синтетические данные, временные каталоги и подмены процессов,
USB/SD, mount/loop и сетевых ответов. Реальная сеть запрещена общей
autouse-фикстурой. Набор не требует оборудования, привилегий или соседних проектов;
его успех не подтверждает аппаратную совместимость.
Линтеры и форматтеры запускаются только по прямой просьбе владельца.

## Исходники и тесты

В корне `src/iroll/` находятся метаданные пакета и точка входа `cli.py`.
Остальной код сгруппирован по ответственности:

| Подпакет | Ответственность |
| --- | --- |
| `common` | Файловые проверки, пути, синхронизация, блокировки и владение процессами |
| `host` | Зависимости ПК, платформы и окружение компиляторов |
| `components` | Реестр компонентов, закреплённые архивы и подготовка исходников |
| `rollout` | Сборка, рабочие деревья и проверяемая выкладка |
| `card` | План подготовки SD, Linux-операции, разбор mountinfo и устойчивый журнал |
| `sdk` | Поиск SDK, безопасная распаковка, подготовка и закреплённый рецепт |
| `emulation` | Манифест, BIOS, входные профили и подготовка ресурсов геймпадов и шейдеров |

CLI не содержит прикладные операции, а нижние слои не зависят от CLI.
Импорт и создание сервисов не приобретают ресурсы и не запускают процессы;
операции и освобождение ресурсов выполняются явно.
Ресурсы читаются через `importlib.resources`, без зависимости от checkout.

Иерархия `tests/iroll/` повторяет исходники: например,
`src/iroll/sdk/discovery.py` соответствует `tests/iroll/sdk/test_discovery.py`.
CLI проверяется в `tests/iroll/test_cli.py`. Общие фикстуры находятся в
`conftest.py` ближайшего общего каталога; специфичные для карты, SDK и эмуляции —
в соответствующих подкаталогах. Проверяется публичное поведение, не приватные методы.
При работе с checkout следуйте проектным `AGENTS.md` и `IDLE.md`.

## Ресурсы

Готовые файлы для SD собраны в `src/iroll/resources/sd/`:

```text
resources/sd/
├── common/
│   ├── INSTRUCTIONS.md
│   └── system/retroarch/
│       ├── padconf/
│       │   ├── 0810-0001.cfg
│       │   └── 20bc-5500.cfg
│       └── shaders/libretro/interpolation/
│           ├── sharp-bilinear-simple.glslp
│           └── shaders/sharp-bilinear-simple.glsl
└── rk3032/
    └── system/iman/iman.json
```

Внутри `common/` и `rk3032/` пути повторяют конечное размещение на SD.
Общий слой используется для обеих платформ, профиль iman — только при сборке
iman для RK3032. Дерево не копируется рекурсивно: подсистемы явно выбирают файлы
по платформе и компонентам, сохраняя проверки SHA, staging и порядок публикации.
`card init` использует только инструкцию; `rollout` также обновляет её в корне назначения.
Содержимое закреплённых сторонних шейдеров, включая исходные окончания файлов,
сохраняется без изменений.

Не все JSON являются готовыми файлами SD. У подсистем остаются:

- `emulation/emulation-{linux-x86_64,rk3032}.json` — входные настройки генератора манифеста;
- `emulation/emulation-cores.json` — настройки ядер и игровых платформ;
- `emulation/shader-source.json` — происхождение и SHA закреплённых шейдеров, для отчёта на ПК;
- `sdk/sdk-rk3032.json` — закреплённый рецепт подготовки SDK.

Бинарники и BIOS, внешние ресурсы IGUI, сгенерированные `emulation.json`
и пресеты шейдеров в ресурсном дереве не хранятся.

## Упаковка

Дистрибутив, Python-пакет и команда называются `iroll`. Сборщик — Hatchling;
зависимостей Python времени выполнения нет. Из каталога пакета:

```bash
uv build
```

Wheel содержит пакет с runtime-ресурсами, метаданные и лицензию. Sdist содержит
исходники с теми же ресурсами, тесты и их данные, `docs/`, `README.md`, `LICENSE`,
`pyproject.toml` и workflow с матрицей makeapp. Инструкция, JSON-рецепты и профили,
CFG геймпадов и GLSL-шейдеры остаются в обоих архивах;
тесты и пользовательская документация в wheel не входят.
Проверяйте состав архивов перед публикацией.

Lock-файлы, окружения, кеши, firmware, дампы, входы и результаты операций
не входят в дистрибутивы. Собственный код — BSD-3-Clause;
сторонние ресурсы и собираемые компоненты сохраняют свои условия распространения.
