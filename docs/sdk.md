# SDK RK3032

SDK нужен для сборки RetroArch и C/C++-ядер под штатный Linux RK3032.
IGUI и iman используют отдельную статическую Rust/musl-цель.
Текущий CLI всё равно ищет и проверяет SDK для `deps` и `rollout` с
`--platform rk3032`, даже при выборе только IGUI и iman.

## Входы и зависимости

Подготовка выполняется на ПК без `sudo` и без обращения к USB, SD или NOR устройства.
Нужны `sh`, Make, `pkg-config`, `unsquashfs` (`squashfs-tools`), `readelf`
(`binutils`), `file`, `grep`, `sed` и `readlink` (`coreutils`). ARM-компиляторы
берутся из архива Bootlin; Rust для подготовки SDK не нужен.
Недостающие программы перечисляются до распаковки.

`--nor` принимает **обычный локальный файл физического NOR**, не устройство.
Рецепт `rk3032-stock-1` требует файл размером 16 МиБ с SHA-256:

```text
9c22c776e8768e0b8e1fa6a66b70b2ca4f76e6d3cee1d2fbc8207f2c87828b17
```

Владелец предоставляет этот сохранённый файл отдельно. Iroll не скачивает NOR,
не создаёт бэкап оборудования и не копирует полный дамп при подготовке SDK.
Другой образ нельзя подставить без изменения и согласования рецепта.

## Подготовка

Из выбранной рабочей директории:

```bash
iroll sdk prepare --platform rk3032 --nor /path/to/nor.bin
```

| Параметр | Назначение и значение по умолчанию |
| --- | --- |
| `--sdk` | Каталог результата: `in/sdk/rk3032/` |
| `--downloads` | Корень загрузок: `in/downloads/`; архивы SDK — в его `sdk/rk3032/` |
| `--logs_dir` | Корень отчётов ПК: `logs/` |
| `--json` | Результат в stdout отдельно от сообщений в stderr |

Все относительные пути считаются от рабочей директории; параметры независимы.
Отсутствующие архивы скачиваются по закреплённым HTTPS URL, каждый сверяется
по SHA-256. Отдельного offline-флага нет; при наличии всех архивов их повторная
загрузка не нужна.

[`sdk-rk3032.json`](../src/iroll/sdk/sdk-rk3032.json) закрепляет состав:

- Bootlin ARMv7 hard-float 2018.11-1;
- архивы заголовков libdrm 2.4.97, Mesa 18.3.6, ALSA 1.1.8, eudev 3.2.7 и zlib 1.2.11;
- выбранные библиотеки и загрузчик из SquashFS NOR по смещению `0x580000`,
  включая glibc 2.29 и vendor Mali;
- заголовки, linker-симлинки и файлы `pkg-config`.

Bootlin релокируется штатным `relocate-sdk.sh`. Заголовки ALSA готовятся штатными
`configure` и `make -C include install`, с явными разными `--build` и `--host`:
ARM-тесты не запускаются даже при наличии binfmt/QEMU. Остальные заголовки
копируются из проверенных архивов; библиотеки NOR не пересобираются.
Сторонние исходники и Makefile не патчатся.

## Проверка и повторное использование

Распаковка идёт в соседний `.iroll-sdk-*` на той же файловой системе.
После проверки состава и C/C++-линковки дерево переименовывается в назначение,
повторно релокируется и проверяется по конечному пути. Проверяются ARM ELF,
hard-float загрузчик и отсутствие требований glibc новее 2.29.
Целевые программы не запускаются; это не проверка EGL/DRM, звука или эмуляции на плате.

Соседний `.rk3032.iroll-sdk.json` содержит отпечатки рецепта, NOR и всего дерева,
включая симлинки. Повтор команды сверяет эти входы и возвращает `SDK_REUSED`
без распаковки и сборки, сохраняя отчёт нового запуска.
Изменённый SDK или несовпадающая запись состояния отклоняются, не исправляются молча.

**Существующий SDK без записи состояния не перезаписывается и не принимается на веру.**
Для подготовки рядом с прежним SDK выберите новое назначение через
`--sdk /path/to/new-sdk`, затем передавайте тот же путь в `deps` и `rollout`.
Принудительной замены и автоматической миграции нет.

## Требования к установленному SDK

В `bin/` или `host/bin/` должен быть ровно один полный комплект `gcc`, `g++`
и `ar` с общим префиксом `arm*-linux-gnueabihf-`.
`gcc -print-sysroot` должен возвращать абсолютный путь внутри SDK.
Sysroot содержит заголовки, библиотеки и `.pc` для `alsa`, `egl`, `gbm`, `glesv2`,
`libdrm`, `libudev` и `zlib`; glibc — не новее 2.29.
Обычный современный distro cross-compiler не заменяет этот sysroot.

```bash
iroll deps --platform rk3032
iroll deps --platform rk3032 --sdk /path/to/new-sdk
```

Для собственного Linux с другим userspace нужен отдельный согласованный sysroot,
не безусловное удаление библиотек NOR. `rollout` сам подготовку SDK не запускает.

## Ошибки и отмена

Обработанная ошибка, Ctrl+C или SIGTERM удаляют только новый SDK и его временные
файлы; отчёт остаётся в `logs/sdk-prepare/<run>/` или выбранном `--logs_dir`.
При аварийном завершении возможны остатки `.iroll-sdk-*` и
`.rk3032.iroll-preparing`. Маркер блокирует подготовку и использование SDK в
`deps`/`rollout`; автоматического продолжения или удаления нет.
Проверьте остатки вручную только при отсутствии работающих процессов.

Каталоги загрузок, отчётов и родитель SDK блокируются на время подготовки.
Не изменяйте SDK и его состояние параллельно с подготовкой или сборкой.
