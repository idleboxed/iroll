# Инструкции агента

Используй [IDLE.md](IDLE.md); уточнения этого проекта имеют приоритет.

## Проект

`iroll` — переносимое CLI-приложение на Python для подготовки SDK RK3032,
сборки и выкладки приложений на ПК и отдельной явной подготовки SD.
Программа не запускает приложения и не записывает NOR. SDK подготавливается
из закреплённых архивов и обычного локального файла NOR, без доступа к устройству.
Рабочие пути задаются пользователем или считаются от текущего каталога;
не привязывай пакет к расположению монорепозитория и соседним проектам.

Код разделён по предметным пакетам в `src/iroll/`, тесты повторяют их иерархию
в `tests/iroll/`. CLI содержит только аргументы, взаимодействие с пользователем,
представление результата и коды завершения. Готовые SD-ресурсы находятся в
`src/iroll/resources/sd/`: общие — в `common/`, профиль платы — в `rk3032/`;
внутри каждого слоя пути повторяют размещение на SD. Входные профили, рецепты
и метаданные происхождения остаются у использующей их подсистемы.
Все ресурсы читаются через `importlib.resources`; выкладывай только явно
выбранные файлы, не копируй дерево ресурсов целиком.
[Структура и проверки](docs/development.md).

## Уточнения

- Имя дистрибутива, Python-пакета и команды — `iroll`.
- Локальная установка CLI: `uv tool install --force -e .`; разработка и проверки:
  `ma tools` и `ma tests` из каталога пакета, только на Python 3.12.
  Это проектное исключение из способа установки по умолчанию в IDLE.md.
- Wheel содержит пакет, необходимые ресурсы, метаданные и лицензию;
  sdist включает также тесты, их данные и документацию. Тесты в sdist —
  проектное исключение из общих правил IDLE.md.
- Тесты не требуют оборудования, внешней сети и привилегий. Подменяй внешние
  взаимодействия, не проверки безопасности. Офлайн-проверки не подтверждают
  работу на RK3032 или исправность реальной SD.
- Новые команды и параметры CLI, изменение проверок безопасности и патчи сторонних
  зависимостей требуют предварительного явного согласования с владельцем.
  Сохраняй байты и уведомления закреплённых сторонних ресурсов.
- Линтеры и форматтеры запускай только по прямой просьбе владельца.
  При правках только Markdown проверяй просмотром формат и изменённые ссылки,
  без тестов, импорта приложения и сборок.
- Не запускай аппаратные операции без отдельного согласования. `card init`
  разрушителен и сам повышает права через `sudo`; эту команду выполняет только
  владелец в своём терминале, не агент. Не ослабляй геометрию, root/card guards,
  подтверждение, автоматическую фиксацию и повторную проверку идентичности носителя.
- Выкладка пофайловая, не атомарное обновление всего комплекта. RO-политика
  игрового runtime отложена; малое число записей и периодическое сохранение SRAM
  не означают устойчивость к отключению питания. Границы — в
  [руководстве выкладки](docs/rollout.md#публикация-и-отмена) и
  [политике сохранений](docs/emulation.md#сохранения-и-записи).
